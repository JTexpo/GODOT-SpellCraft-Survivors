# Development Log

## 2026-11-18: Sprint 0 start

Decisions (details in `sprint-0-design.md`):

- Godot 4.7.2 from Homebrew, not pinned locally. CI pins the version later. Web export templates are installed when the first web export is needed.
- Compatibility renderer, 480x270 internal resolution, `viewport` stretch with integer scaling, nearest-neighbor filtering, 2D pixel snap.
- GUT 9.7.1 vendored in `addons/gut/` from the release zip. Verified to run on Godot 4.7.2.
- No autoloads. Input goes through Input Map actions only. Touch is a virtual joystick for movement (aiming/casting on touch is a later design decision).
- Work happens on the `sprint-0-foundation` branch, not on `main`.

## 2026-11-18: Sprint 0 implementation notes

- Godot 4.7 ships a native `VirtualJoystick` class, so ours is `TouchJoystick`. Worth evaluating whether the native one can replace it later.
- `export_presets.cfg` has a Web preset with `variant/thread_support=false` set explicitly (single-threaded). Not yet exported: the web export templates for 4.7.2 aren't installed. Whether single-threaded is the 4.7 default is unconfirmed, and the explicit setting makes that moot.
- The Input Map was generated by a one-off headless script and saved to `project.godot`. Movement deadzone is 0.2, the other actions 0.5.
Input map script (scratchpad) now sets device=-1; project.godot regenerated.

## 2026-11-19: Sprint 1 stress test (desktop)

Command: `godot --path . res://scenes/world/stress_test.tscn -- --enemies=N --seconds=10` (windowed, Compatibility renderer, vsync off, Apple M1 Mac). The scene keeps N full enemies alive (chasing, active hitboxes and hurtboxes, taking fire from a rotating attacker at 20 shots/s) around a stationary invulnerable player. Frame times come from `_process` delta (wall clock), after a 30-frame warmup.

| Enemies | avg fps | avg frame ms | p99 frame ms |
|---|---|---|---|
| 100 | 940.8 | 1.06 | 1.39 |
| 300 | 733.6 | 1.36 | 1.52 |
| 500 | 535.3 | 1.87 | 8.64 |

Target was 60 fps (16.6 ms per frame) at 300 enemies, with 500 as a stretch goal. Both are met on this machine with a large margin, so no optimization work was needed in Sprint 1.

Caveats:
- This is a desktop result. Phones and browsers run physics on one thread and are much slower, so re-measure once a web build exists (Sprint 15, or earlier if a web export is set up).
- The `avg_physics_ms` and `avg_process_ms` columns (Godot's `Performance` monitors) do not agree with the wall-clock frame times, so they are not used for the verdict.
- The p99 spike at 500 enemies (8.64 ms) is worth watching if the count grows.
- The enemies spawn within 40-200 px of the player and pile onto them, which is close to a worst case for overlap checks.

## 2026-11-19: Bug found by the user

Enemies stopped in front of the player. Each enemy aimed at a random point up to 24 px from the player and stopped there, but the hit boxes are 12 px wide, so enemies that stopped 13-24 px away never dealt damage. Fixed: the random offset now fades out as the enemy closes in. Side effect: enemies converge on the player, which brings back the crowd-stacking question. It is still the decision gate at the end of Sprint 1.
